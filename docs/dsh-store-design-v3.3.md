# DSH 插件商城 · 核心设计方案 v3.3（多服务器源与联邦互联）

> 版本：v3.3 · 2026-08-14 · 基于 v3.2 增补，未提及章节不变
> 背景：项目开源，任何人可自部署服务器。本轮新增：① 用户端服务器源机制 ② 服务器间联邦（共享用户/组/资料等）③ 选择性共享与实时共享（负载均衡）
> 配套原型：`dsh-store-ui-prototype.html` 已同步更新。

---

## F1. 用户端服务器源机制

### F1.1 源模型

```
源 = { id, name, url, access_password, enabled, 内置标记, 延迟(ms, 实测) }
```

| 规则 | 说明 |
|---|---|
| **内置默认源** | 初始项目只内置**官方源**（我的服务器），其访问密码作为**原始密码**内置在默认配置里——用户开箱即用，零配置 |
| **自行添加** | 用户可添加他人部署的源：**服务器网址 + 该源管理员设置的访问密码**，两项缺一不可 |
| **自部署改密** | 他人部署后可在自己管理端改访问密码（`server.access_password`）；改密后旧客户端需更新密码才能继续用——这是私有部署的准入控制 |
| **多源并存** | 可添加多个源；设置页可启停、切换、测速 |

### F1.2 多源下的数据策略

- **主源制**：同一时刻只有一个"主源"提供数据通道（插件/组/榜单），避免多源数据在客户端打架；
- 其余源为候选：主源不可达时**自动故障转移**到可用源（按延迟排序）；
- 写操作（建组/点赞/恢复）永远落到主源；
- 源切换 = 切换整套数据命名空间（不同源的组和点赞互不混淆，本地按源 ID 分库存储）。

## F2. 服务器联邦建立（管理员侧）

### F2.1 两级密码（严格分离）

| 密码 | 用途 | 谁知道 |
|---|---|---|
| 访问密码 | 用户客户端连接本服务器 | 该服用户 |
| **联邦密码** | 服务器与服务器互联 | 仅双方管理员 |

### F2.2 握手流程（分享者主动发起，被分享者接收）

```
管理员 A（发起方）在管理端输入：对方服务器地址 + 对方的联邦密码
  → A 向 B 发起联邦邀请（携带 A 的地址、公钥、拟共享内容清单）
  → B 管理端"联邦互联"页出现待处理邀请
  → B 管理员审核 → [接受] / [拒绝]
  → 接受后：双方互换凭证、协商共享范围 → 联邦关系建立
```

- 联邦密码错误 → 邀请根本无法生成有效签名，B 侧无感知（防探测）；
- 任一方可随时**断开联邦**；断开后处理见 F4.4。

## F3. 共享内容矩阵（哪些共享、哪些不共享）

| 数据 | 共享？ | 方式与理由 |
|---|---|---|
| 插件索引（基础字段） | 可选 | 各服本来都爬 GitHub，基础数据重复价值低；**有共享价值的是各服的"人工覆盖、质量分、汉化（若开启）、提速收录结果"**——共享这些等于共享运营成果 |
| 组合（Bundle） | ✅ 核心价值 | 跨服用户可见/可装对方服务器的组 |
| 点赞数 / 下载量 | ✅ 聚合显示 | 跨服合并计数，标注"全网" |
| 趋势榜（星增） | 可选 | 数据同源（GitHub），直接共享省各自计算 |
| **安全情报（拉黑列表、风险标签、扫描结果）** | ✅ 强烈建议 | 一家发现恶意包，全网拦截——安全价值最高的共享项 |
| 用户资料 | ⚠️ **不复制，只联邦认证** | 见 F3.1 |
| 用户云端安装清单 | ❌ 不共享 | 隐私数据，只存用户的 home 服务器 |
| 公告 / 更新提醒 | ❌ 各自独立 | 各服运营自己的公告 |
| 举报 / 审核队列 | ❌ 各自处置 | 但处置结果（下架某组）会随组数据同步 |

### F3.1 用户的联邦化（共享用户的正确姿势）

**不复制用户资料，做"联邦身份"**：
- 用户账号永远属于 **home 服务器**（他注册时连的那个源）；
- 用户在 B 服浏览时想点赞 → B 服把认证请求**转发给用户的 home 服**验证（home 服签发短期联邦凭证，B 服只认凭证不存资料）；
- 显示形态：`liwei@官方源`——跨服点赞计数正常聚合，但 B 服数据库里**不落地** liwei 的资料；
- 这样满足"共享用户"的目标（用户跨服可用、互动计数互通），又不触碰隐私红线。

## F4. 共享的数据适配（防重复与变更一致性）

### F4.1 联邦 ID 命名空间（防冲突的根本）

- 所有跨服可见对象使用 **全局限定 ID**：`{源域名}:{本地ID}`，如 `store.example.com:combo_42`；
- 客户端与各服展示时可隐藏前缀（同名组加来源徽标区分）；
- 组 slug 冲突不再可能（命名空间隔离）。

### F4.2 去重键

| 对象 | 去重键 |
|---|---|
| 插件补充数据 | `full_name`（owner/repo，天然全局唯一） |
| 组 | 联邦 ID（slug 仅服内唯一） |
| 用户 | `github_id` + home 服域名 |

### F4.3 变更适配（数据变了怎么办）

- **home 权威原则**：每个对象只有它的源服务器能改；其他服只持只读副本；
- 副本同步携带 `版本号 + updated_at`；副本过期自动刷新；
- 同一对象的**人工覆盖只在本服生效**，跨服以各自 home 版本为准（A 服改写的简介不影响 B 服自己改写过的——人工运营成果不互相覆盖）；
- **删除传播用墓碑（tombstone）**：源服删除某组 → 下发一条墓碑记录 → 各联邦服副本标记删除而不是直接抹掉（防止旧副本复活）；
- 点赞聚合显示时按目标联邦 ID 汇总各服计数。

### F4.4 断开联邦的适配

- 副本保留但标记"已断联"，不再刷新；
- 已断联源的组：可浏览缓存，安装时提示"来源服务器已断开，内容可能过期"；
- 重连后按版本号增量追平。

## F5. 共享模式（可选内容 + 可选实时 + 负载均衡）

### F5.1 两种共享模式（建立联邦时按内容逐项选择）

| 模式 | 说明 | 适用 |
|---|---|---|
| **定时快照共享** | 按周期（可配，默认 1h）拉取对方变更 | 插件补充数据、趋势榜 |
| **实时共享** | 长连接推送变更事件（组、点赞、安全情报秒级互通） | 组、拉黑列表 |

共享内容逐项勾选：插件补充 / 组合 / 计数聚合 / 趋势榜 / 安全情报（矩阵见 F3）。

### F5.2 实时共享 = 负载均衡模式

- 开启"全量实时共享"的联邦集群内，各服数据最终一致（秒级）；
- **线路选择**：各服互测 RTT 并定期上报形成节点延迟表；客户端请求 manifest 时带上各源实测延迟，**由服务器按"延迟最低且健康"原则给出推荐节点**（或重定向）；客户端也可自行直连测速兜底；
- 单服故障：客户端自动切到联邦内健康节点，数据无差别（因为实时一致）——这就是负载均衡 + 高可用。

## F6. 安全与隐私（联邦面）

- 联邦通道独立鉴权（双向凭证 + 签名），与公开 API 完全隔离；
- 联邦密码与访问密码分离，均可独立更换（换联邦密码需重新握手）；
- 全 TLS；联邦事件留审计（谁发起、谁接受、共享了什么、何时断开）；
- 恶意联邦成员处置：一键断开 + 本地清除其副本 + 其推送的安全情报标记存疑；
- 用户隐私红线：资料不出 home 服；云端安装清单不参与任何共享。

## F7. 配置 / API / ADR 增补

**配置新增**：`server.access_password`（访问密码）、`federation.enabled`、`federation.secret`（联邦密码）、`federation.share.*`（各项开关）、`federation.mode`（snapshot/realtime）、`lb.node_rtt_interval`。
**API 新增**：`POST /api/v1/federation/handshake`（服间）、`GET /api/v1/federation/changes?since=`（增量拉取）、联邦事件推送通道（长连接）、`GET /api/v1/nodes`（联邦节点与延迟表）。

**ADR**：

| 决策 | 结论 | 理由 |
|---|---|---|
| 默认源密码 | 内置"原始密码"开箱即用 | 新手零配置；私有部署自行改密 |
| 用户共享 | 联邦认证，不复制资料 | 跨服可用与隐私兼得 |
| 命名冲突 | 联邦 ID = 域名:本地ID | 根治重复，天然可追溯来源 |
| 变更权威 | home 服权威 + 墓碑删除 | 防止副本互相覆盖、旧数据复活 |
| 人工覆盖 | 不跨服覆盖 | 保护各服运营成果 |
| 断联数据 | 保留缓存 + 过期提示 | 用户已装的组不因断联而损坏 |
