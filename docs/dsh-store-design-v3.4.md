## M1. 换源状态机与数据迁移

### M1.1 换源的三种场景（行为截然不同）

| 场景 | 登录态 | 首次同步弹窗 | 原因 |
|---|---|---|---|
| ① 换到**独立新源**（无联邦关系） | **自动登出 GitHub** | **弹**（见 M1.2） | 用户凭证由旧源签发，换源即失效；新源没有你的任何数据 |
| ② 换到**联邦但非 LB** 的源 | 登出（可用联邦身份重新登录） | 弹 | 组/点赞因联邦聚合部分可见，但云端清单仍在 home 服 |
| ③ 换到 **LB 集群内**的源 | **保持登录，无感切换** | **不弹** | 实时共享使新源已有全部数据（含用户数据）——**不算第一次来** |

> 判定依据：manifest 中携带的集群标识。源属于同一 LB 集群（`cluster_id` 相同）→ 走场景③。

### M1.2 首次到新源：同步弹窗与设置

```
检测到"首次连接某独立/联邦源"（本地无该源的访问记录）
  → 弹窗："检测到本地存有插件数据（台账/收藏/订阅/我的组）。
           是否同步到当前源？【去同步】 【暂不】"
  → 点【去同步】→ 跳转设置中的「同步数据」区：
       · [立即同步本地数据到本源]
       · ☑ 以后到新源自动同步（开关，默认关）
  → 选"暂不"：数据仅留本地，该源下次不再弹（记忆选择，可在设置改）
```

### M1.3 提交数据的查重（客户端 + 服务端双防线）

源间数据共享意味着**新源可能已有重复数据**，提交必须查重：

| 对象 | 查重键 | 冲突处理 |
|---|---|---|
| 我的组 | 组内容指纹（成员集合+名称归一化） | 客户端预检提示"该源已存在相似组：保留两份 / 跳过 / 合并成员"，用户选择后执行 |
| 点赞 | 用户 + 目标联邦 ID | 幂等，重复提交自动去重（服务端唯一约束兜底） |
| 云端安装清单 | 目标 + 类型 | 服务端 upsert，重复即更新 |
| 收藏/订阅 | 目标联邦 ID | 幂等合并 |

流程：客户端先拉新源侧已有数据做**预检**（把冲突项列给用户选），提交后服务端**二次查重**（唯一约束 + 合并日志），两次都过才入库。所有合并动作留审计。

## M2. 负载均衡源的自动发现与免密加入

### M2.1 发现与提醒

- LB 集群成员信息随主源数据通道下发（`cluster_id` + 节点列表 + 各节点 RTT）——**信息传递依靠网址**；
- 客户端发现"当前源所属 LB 集群出现新节点"→ 通知提醒（归入"源与系统"类）：
  > "发现负载均衡源 mirror-02.cn（与本源数据实时同步）。是否加入备用源列表？加入**无需密码**。"
- 同意 → **免密自动添加**（LB 集群内共享信任，访问凭证在集群内互认）；
- 设置中也可随时"**搜索本源的其他负载均衡源**"手动添加（从 manifest 节点列表列出，一键加入）。

### M2.2 LB 切换 = 无感

- 主源宕机 → 自动切到集群内健康节点：登录保持（凭证集群内互认）、数据无差别、不弹任何同步窗口；
- 用户在源列表看到 LB 成员带「⚖️ 负载均衡」徽标，与独立源视觉区分。

## M3. 通知分类体系（不再堆在一起）

通知中心改为**分类 Tab**，每类独立计数、独立处理：

| 分类 | 内容 | 默认动作 |
|---|---|---|
| 📦 **更新** | 插件有更新 / 组内成员更新 / 订阅组新增插件 | 一键更新 / 忽略 |
| ❓ **待确认** | 库外插件上报询问、组重复冲突选择 | 需用户决策，不消失 |
| 🌐 **源与系统** | 新 LB 源发现、换源结果、同步完成、源断联 | 知晓类，可一键清除 |
| 📢 **公告** | 保持独立抽屉（已有），不进通知中心 | 点叹号查看 |

- 悬浮球蓝点 = 前三类未读总数；打开面板默认落在**有待处理项的分类**；
- 每类支持"全部忽略"；分类内条目沿用 v3.1"点击定位高亮"规则。

## M4. 服务器间站内信

- 联邦关系建立后，管理端「联邦互联」页每个成员行提供「✉️ 消息」入口；
- 纯文本短消息（长度上限可配置，默认 1000 字）、频率限制（防骚扰）、可走实时通道；
- 用途：协商共享范围调整、维护窗口预告、安全情报沟通（如"我这边拉黑 X 了，建议核查"）；
- 消息记录双方各自留存 + 审计；断开联邦后通道关闭（历史消息保留只读）。

---

## M5. LB 集群的公告分标签

- LB 集群内**全部数据实时共享**，但**公告例外：各服独立发布**；
- 公告对象增加 `origin_server` 字段；客户端公告面板顶部加来源标签筛选：
  `全部 | 官方源 | mirror-01.cn | …`（标签随集群成员动态生成）；
- 互不干扰：A 服发布的公告只代表 A 的运营声音；叹号提醒按"任一来源有新公告"触发，面板内默认展示"全部"。

## M6. 配置 / API / ADR 增补

**配置新增**：`sync.auto_on_new_source`（默认关）、`lb.auto_join_prompt`（默认开）、`message.max_length`、`message.rate_limit`。
**API 新增**：`POST /api/v1/me/migrate`（数据提交，带预检响应）、`GET /api/v1/cluster/nodes`（LB 节点）、`POST /federation/message`（服间站内信）。

**ADR**：

| 决策 | 结论 | 理由 |
|---|---|---|
| 换源登出 | 独立/联邦源登出，LB 集群内保持 | 凭证是源签发的；LB 内凭证互认是集群定义的一部分 |
| 首次同步 | 弹窗询问 + 可设自动 | 数据主权在用户，默认不自动上传 |
| 查重 | 客户端预检 + 服务端约束双防线 | 源间共享必然产生重复，单边拦不住 |
| LB 加入 | 免密（集群内信任） | LB 即"同一台逻辑服务器"，再加密码是伪安全 |
| 通知 | 三类分 Tab + 公告独立 | 堆在一起 = 更新提醒被淹没，违背"通知必可达"原则 |
| LB 公告 | 共享数据但公告按源分标签 | 一体的是数据，独立的是各服的运营声音 |
